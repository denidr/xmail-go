# Unify protocol dispatch in `account.Service` into one registration table

`account.Service` registers each Mailer protocol through a single table entry (a small record of the constructors that protocol supports) instead of the six separate factory fields/setters it grew during the phased build, and test-connection reuses the `TestConnection` method that `mailer.Sender`/`mailer.Fetcher` already carry rather than a dedicated `ConnTester` seam. This reverses an earlier decision to leave the `(cfg, username, secret)` clump and the repeated protocol switches as-is: the duplication turned out to be load-bearing — a diverging copy of the dispatch logic already caused a real bug, and adding a protocol had become a four-declaration edit spanning three packages. The trade-off accepted here is a slightly less type-safe lookup (one `Protocol` record keyed by name) in exchange for a smaller `Service` interface and one place that knows how a protocol maps to its constructors.

Status: accepted. Implemented — `account.Service` now holds one `Protocol` registration table (`internal/account/protocol.go`), wired by three `RegisterProtocol` calls in `internal/app.wireMailer`; `ConnTester`, the four factory types, and the six setters are gone, and test-connection reuses the `TestConnection` method each `Sender`/`Fetcher` already implements.
