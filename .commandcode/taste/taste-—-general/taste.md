# Taste — General
- Communicates in Indonesian and expects responses, plans, and docs written in Indonesian. Confidence: 0.9
- Prefers a plan-first workflow: wants a PRD plus a detailed plan and scaffolding produced before implementation coding starts. Confidence: 0.9
- Wants plans/requirements documents persisted as real `.md` files in the repo, not delivered only as ephemeral "plan mode" output. Confidence: 0.85
- Expects substantial deliverables (reports, reviews, analyses) to be written out as `.md` files in the repo rather than only posted in chat — e.g. asked for an inline code-review report to become a `.md` file at the repo root. Confidence: 0.8
- Works goal/checklist-driven: asks for everything in the plan to be implemented and verified as immediately usable/complete, and wants the plan updated with a note about any additions or gaps after each phase. Confidence: 0.85
- Insists on review/verification as an iterative loop: after implementation, asks for a crosscheck/audit against the plan rather than accepting completion at face value, and repeatedly re-requests re-verification ("check again") after each round of fixes until no open behavioral bugs remain. Confidence: 0.9
- Wants the audit/verification loop run autonomously for many back-to-back rounds without pausing for confirmation between them — e.g. "check again, keep going until 10x" — rather than stopping after each round to report and ask whether to continue. Confidence: 0.6
- Expects bug fixes to come with a regression test that is actually proven to catch the bug — temporarily reintroduce the fault (or disable the fix), confirm the new test fails with the exact buggy output, then restore — and wants that rigor kept up round after round. Confidence: 0.75
- Expects the agent to independently reproduce and confirm a suspected defect (its own failing test / repro) before fixing and declaring it done, rather than trusting a prior fix, the docs, or an earlier "all green". Confidence: 0.7
- Reports field bugs from actually running the shipped/installed artifact (double-clicking the built Windows exe) rather than from reading code, and expects the fix to be validated end-to-end on the rebuilt release binary through the same repro path — not only by unit tests at the source level. Confidence: 0.65
- Communicates fixes terse — a short "check again / sudah diperbaiki" with no pointer to what actually changed — expecting the agent to discover and verify the changes autonomously. Confidence: 0.7
- When findings/bugs are raised, wants them fixed directly in the code ("tolong kamu fix langsung", "fix semua issue yang belum fix") rather than just reported or documented — prefers the agent to go ahead and apply the fixes, and to clear the whole open-findings list rather than a cherry-picked subset. Confidence: 0.85
- Holds a production-grade bar: clear, well-structured logging and reliability matter even for small services. Confidence: 0.85
- Prefers high-effort, comprehensive work (extensive testing plus documentation) over minimal quick changes. Confidence: 0.7
- When presented with a set of options/candidates, leans toward exploring/doing all of them ("explore semua", "lanjut semua") rather than picking a subset — wants exhaustive coverage over a cherry-picked slice. Confidence: 0.7
- Expects a configuration/default change (e.g. changing the service's default listen port) to be propagated consistently to every occurrence — source, tests/fixtures, env examples, Dockerfile/Makefile, and all docs/Postman artifacts — then verified with a final search so no stale value remains. Confidence: 0.6
- Doesn't want the agent to stall on pragmatic setup/config steps awaiting approval — when the agent flagged first-run `.env` generation as "a product decision" and withheld it, the user replied "generate .env dong nanti saya update", i.e. just produce sensible ready-to-use defaults (with inline comments per key) and leave the fine-tuning to him. Confidence: 0.6
- Likes rich, browsable review deliverables: accepts/expects self-contained HTML reports (rich styling, before/after diagrams) opened in the browser as the artifact for design/architecture reviews, not only plain markdown. Confidence: 0.5
